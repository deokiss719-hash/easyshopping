# 2026-09-30 결제 흐름 단순화

- 무료: 개인별 핵심 성향 첫 두 문단(확장 설정은 세 문단). 서버에서 유료 본문을 제외한다.
- 핵심 성향 뒤에 가격과 이어 읽기 버튼을 먼저 배치한다. 실제 목차는 아래, 실제 샘플은 접어서 제공한다.
- 상품/환불 정보는 클릭해서 펼치며, 결제 전 동의는 유지한다. 조회 링크/복구 코드 저장은 요구하지 않는다.
- 결제 버튼: 토스로 결제하기. 실제 계약은 토스페이먼츠 카드 결제임을 인접 문구로 명시한다. TossPay 전용 간편결제로 바꾸지 않는다.
- 결제 후 전체 펼치기와 인쇄/PDF 저장 제공. 브라우저 인증 1시간 및 재열람 한계를 구매 안내/정책/저장 영역에 명시한다.
- 기존 데이터, 결제 금액 검증, 중복 처리, 기존 링크/복구 API는 유지한다.

## 근거와 가설
Baymard의 결제 UX 연구는 단계 수보다 고객이 고려해야 하는 입력/요소 수를 줄이는 것을 강조한다.
https://baymard.com/research-articles/checkout-flow-average-form-fields
https://baymard.com/learn/checkout-flow-ux-optimization

이를 불필요한 복구 수단 저장 절차 제거 및 부가 정보의 선택 공개에 적용했다. 무료 두 문단이 사주 상품에서 최적이라는 실증 자료는 없으므로 전환 개선 가설이다. 기존 무료 열람/checkout/paid/refund 이벤트로 이후 성과를 판단한다. 가짜 할인 기한, 허위 재고, 미래 보장은 사용하지 않는다.

## 검증
- 전체 자동 테스트 532개 통과(서버 무료 projection, 동의만으로 주문 생성, 기존 결제 보안/환불/베타 호환 포함).
- 격리된 PGlite/demo 환경, 390x844 모바일: 입력→짧은 무료 결과→접힌 구매 안내→모의 승인→전체 보고서 확인. 가로 넘침 없음.
- 전체 펼치기 후 미완성 animation span 0개.
- 인쇄 미리보기에서 보고서만 10페이지 PDF로 구성, 구매/결제 조작부 제외 확인.
- 실제 카드 청구는 이번 검증에서 수행하지 않음.
