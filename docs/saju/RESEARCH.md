# 사주 서비스 계산·운영 조사와 결정 (2026-09-29)

## 초보자를 위한 요약

사주팔자는 생년·월·일·시를 각각 천간과 지지 두 글자로 표현한 네 기둥입니다. 달력 계산으로 얻는 **글자**와 그 글자에 전통적 의미를 부여하는 **해석**은 다릅니다. 천문연구원의 달력 자료가 명리 해석의 과학적 타당성까지 보증하지는 않습니다. 첫 버전은 외부 AI를 사용하지 않고, 고정된 해석 규칙을 계산 데이터와 연결합니다.

- 음력 생일은 한국 음력 표로 먼저 양력 날짜로 변환합니다. 중국 음력과 혼용하지 않습니다.
- 연주는 설날이 아니라 입춘 **순간**, 월주는 음력 1일이 아니라 12개 절입 **순간**에 바꿉니다.
- 출생지 IANA 시간대의 표준시·서머타임 이력을 적용합니다. 한국 1954~1961년 UTC+08:30, 1987~1988년 서머타임 등도 포함합니다.
- 절기 라이브러리는 UTC+8 시각을 반환합니다. 출생 순간을 UTC+8로 변환해 연·월주를 비교합니다. 일·시주는 출생지 현지 시계를 사용합니다.
- 일주는 자정에 바뀝니다. 23시부터 다음 날로 보는 학파와 다릅니다. 시주의 천간도 자정 기준 일간에서 직접 계산합니다. 진태양시·경도 보정은 적용하지 않습니다.
- 오행은 확정된 겉글자의 천간/지지 대표 오행을 1개씩 집계합니다. 지장간은 별도 공개합니다. 단순 개수는 왕쇠·용신·운의 좋고 나쁨을 뜻하지 않습니다.
- 십성은 일간 대비 대상 천간의 오행 생극과 음양 관계로 결정합니다. 관계를 계산하는 규칙은 고정할 수 있지만 성격·재물 해석은 전통적 가설입니다.
- 대운은 월주에서 순행/역행하며 10년 단위로 표시합니다. 전통 방향 규칙에 쓰이는 성별을 입력받지 않으므로 **두 방향을 모두 공개**하고 하나를 정답으로 추천하지 않습니다. 앞/뒤 절입까지 실제 경과 일수 / 3을 시작 나이의 근사값으로 사용합니다. 정확한 대운 전환 날짜·성별 기반 단일 방향 서비스가 아닙니다.
- 세운은 해마다 입춘부터 다음 입춘까지의 간지입니다. 해석 v1은 2026~2030년으로 고정합니다. 새해에 기존 구매 보고서를 임의 변경하지 않습니다.

## 입력 범위와 불확실성

1900년 이후, 만 14세 이상. 국가 전체의 시간대가 여러 개인 경우 대표 도시별 선택지를 사용합니다. 중국은 상하이 시간대 이력이 적용되는 지역만 지원합니다. 음력 입력은 출생지가 해외여도 **한국 음력**으로 해석합니다. 그 외 지역은 잘못된 자동 추정 대신 미지원으로 안내합니다.

정확한 시각: 분 단위. 서머타임으로 존재하지 않거나 두 번 존재하는 시각은 정확 입력으로 받지 않습니다. 절기 경계 2분 이내는 자료 간 초 단위 차이를 고려해 유료 분석을 중단합니다.

대략적 시각: 선택한 현지 2시간 구간의 매분, 모름: 해당 현지 날짜의 매분을 열거합니다. 서머타임 겹침은 양쪽 offset을 포함합니다. 달라지는 연·월·시주는 확정하지 않습니다. 모름에서는 시주를 항상 숨깁니다. 공통 일주가 없으면 분석을 거절합니다. 시각 범위로 인해 절기일의 연·월주까지 미확정일 수 있습니다.

## 출처와 라이브러리

1. 한국천문연구원 생활천문/역서: https://astro.kasi.re.kr/life/pageView/8 및 https://astro.kasi.re.kr/life/post/calendardata
   - 역법·음양력 비교와 절기 검증의 기준 자료. 2024 입춘 2/4 17:27 KST를 테스트에 고정했습니다.
   - 2024 역서: https://astro.kasi.re.kr/file/astro_almanac_pdf/20231023135218580.pdf
2. 한국 음력 변환 `korean-lunar-calendar@0.3.6` (MIT): https://github.com/usingsky/korean_lunar_calendar_js
   - 개발자가 한국천문연구원 기준 표를 사용한다고 명시한 제3자 구현입니다. 천문연구원 공식 인증 제품이라고 주장하지 않습니다.
   - 2017 음력 윤5/1 → 6/24, 1956 음력1/21 → 3/3 등 공개 예제/윤달 거절 검증.
3. 절기/간지 `lunar-javascript@1.7.7` (MIT): https://github.com/6tail/lunar-javascript
   - API: https://6tail.cn/calendar/api.html / 일자 변경 기준 https://6tail.cn/calendar/lunar.ganzhi.html
   - `getYearInGanZhiExact`, `getMonthInGanZhiExact`, `getDayInGanZhi`, `getPrevJie/getNextJie` 사용. 한국 음력 변환에는 사용하지 않습니다.
   - 라이브러리 `getYun`의 성별 자동 방향을 호출하지 않고 두 방향을 명시적으로 계산합니다.
4. 시간대 `luxon@3.7.2` (MIT) + Node ICU/IANA: https://moment.github.io/luxon/ 및 https://data.iana.org/time-zones/tzdb/asia
   - 런타임 tz 버전을 결과에 저장합니다. ICU 데이터 업데이트 후 경계 회귀 검증이 필요합니다.

## 결제 선택

기존 Express/PostgreSQL 구조와 직접 연결 가능한 토스페이먼츠를 선택했습니다. 결제창 호출 → 서버 금액 검증 → 서버 승인/조회 → DB 권한 반영 구조입니다. 월 구독/간편결제 자체 가입/전화번호 수집 없이 카드 단건 결제를 요청합니다. PG 인증 화면에서 결제사가 별도로 요구하는 정보는 PG의 처리 범위이며 우리 사주 입력 폼에 저장하지 않습니다.

- https://docs.tosspayments.com/guides/v2/payment-window/integration
- https://docs.tosspayments.com/reference (승인·조회·취소)
- https://docs.tosspayments.com/reference/using-api/api-keys
- https://docs.tosspayments.com/guides/v2/get-started/environment
- https://docs.tosspayments.com/guides/v2/get-started/llms-quick-reference (멱등성·웹훅 재검증)
- 공식 테스트 샘플: https://github.com/tosspayments/tosspayments-sample

대안: PortOne은 여러 PG 교체에 유리하지만 초기 단일 상품에는 추가 계층이 생깁니다(https://developers.portone.io/docs/ko/v2-payment/readme). NICEPAY 등 별도 PG도 계약/심사가 필요합니다. 첫 버전은 한 공급자와 단건 결제만 검증해 운영 복잡도를 줄입니다.

`demo`는 PG 없이 모의 승인, `test`는 실제 토스 테스트망, `live`만 과금입니다. 셋을 화면/주문/지표에서 구분합니다. 클라이언트 키만 브라우저에 전달하고 시크릿 키는 환경변수에서만 사용합니다. 승인 응답에서 paymentKey/orderId/통화/금액/잔액/DONE을 모두 확인합니다. 주문별 고정 Idempotency-Key와 행 잠금, 단일 유효 주문 제약으로 중복을 막습니다. 통신 불확실은 confirming/refunding으로 남겨 같은 키로 재확인합니다. 웹훅은 신뢰하지 않고 서버 조회로 검증합니다.

## 환불·개인정보 (검토일 2026-09-29)

법정 최저 제한에 기대어 열람 즉시 환불을 막지 않고, 초기 운영 정책으로 **결제 후 7일 이내 신청 시 열람 여부와 무관한 전액 환불**을 제공합니다. 표시/계약과 다른 공급 등 법정 권리는 별도로 보장합니다. 제17조 예외의 적용 여부를 자동 단정하지 않습니다. 적법한 청약철회 시 환급 기한은 제18조에 따라 처리합니다.

- 전자상거래법 제17·18조: https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률
- 시행령 제6조: https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률시행령
- 디지털콘텐츠 표준약관: https://www.law.go.kr/admRulLsInfoP.do?admRulSeq=2100000216089
- 개인정보보호법 제15·21조: https://www.law.go.kr/법령/개인정보보호법

계약/청약철회 및 결제/공급 기록 5년, 소비자 불만/분쟁 처리 기록 3년, 표시광고 기록 6개월의 법정 구분을 운영자가 지켜야 합니다. 코드의 주문 기록은 5년, 비과금 테스트 기록은 30일로 구분합니다. 외부 상담채널의 불만/분쟁 기록과 광고 변경 이력은 해당 채널/운영 기록에서 별도 관리해야 합니다. 출생 데이터는 이 금융기록에 포함하지 않습니다.

무료 결과 7일, 구매 데이터 1년, 요청 시 즉시 삭제. 데이터는 AES-256-GCM으로 암호화. 개인정보가 없는 날짜/단계/환경/횟수만 분석 집계합니다. IP 제한용 키는 해시로 저장 후 10~60분 만료(복구 15분), 원 IP/출생일/결과를 이벤트나 앱 로그에 기록하지 않습니다. 복구 코드는 난수 256비트·해시만 저장합니다. 7일/1회 링크는 URL fragment로 전달하여 서버 접근 로그와 Referer에 남기지 않고 1시간 HttpOnly 열람 세션으로 바꿉니다. 재발급 시 기존 링크, 복구 시 이전 열람 세션을 무효화합니다.

인프라 운영자는 Render/DB 백업 보존 정책과 개인정보 처리위탁·국외 이전 해당 여부, 판매자 사업자 고지/통신판매 신고, PG 업종 심사를 실제 계약 정보로 확인해야 합니다. 모르는 사업자 정보나 계약 사실을 만들어 넣지 않습니다. 운영 정보가 준비되기 전 실결제는 비활성입니다.


## 상세 해석 v3 (ko-depth-3, 2026-09-29)

### 레퍼런스 조사 범위

사용자 지정 https://www.tosoksaju.com/guija 에서 가상의 1990-01-01 및 1988-08-15,
양력·시각 미상 입력의 공개 결과를 확인했다. 성향을 먼저 제시하고 생활 장면의 예를 들며
인연·재물·시기 등의 주제로 확장하는 구성이다. 실제 구매/유료 본문/내부 해석 엔진은
확인하지 않았다. 동일 알고리즘·유료 콘텐츠 수준을 재현했다고 주장하지 않는다.
원문/인물/후기/가짜할인/공포를 유발하는 확정 예언을 복제하지 않는다.

### 구현 범위

- 기존 달력 엔진/원국 계산은 변경하지 않는다. 달력과 해석 버전은 분리한다.
- 일간+월간 십성: 장점과 과도하게 쓸 때의 점검 주제, 생활 질문/작은 실행 사례를 연결한다.
- 월지: 寅卯辰/巳午未/申酉戌/亥子丑을 절기 월의 봄/여름/가을/겨울로 표기한다.
  계절 가중치나 신강·신약 판정은 추가하지 않는다.
- 지장간: 라이브러리 ZHI_HIDE_GAN/SHI_SHEN에 대응하는 기존 계산값을 사용한다.
  같은 오행(비견·겁재) 지장간의 존재 여부/위치만 확인하며 그 존재를 강약으로 바꾸지 않는다.
- 반복 계열: 연·월·시의 확정 천간만 비겁/식상/재성/관성/인성으로 집계한다.
  기준인 일간을 중복 집계하지 않고 지장간도 가중 합산하지 않는다.
- 관계: 일지의 각 지장간 십성에 해당하는 대화/경계 질문을 제공한다.
- 일·재물: 월간 및 바깥 천간의 재성 유무에 따라 설명을 달리한다. 소득금액·종목·수익률 예측 없음.
- 대운: 순행/역행 각각의 8개 구간에 십성과 월간 계열 비교를 연결한다. 방향을 선택하거나 추천하지 않는다.
- 세운: 2026~2030 고정 간지와 십성, 확정 원국 지지와 동일한 글자의 위치를 확인하고 참고 질문을 제공한다.
- 각 블록은 원본 chart의 경로와 값을 evidence에 저장한다. 생활 사례는 개발자가 작성한 전통 상징 기반
  편집 규칙으로, 경험적으로 검증된 성격/사건 모형이 아니며 천문 자료가 해석의 타당성을 보증하지 않는다.
- 달력 구현 출처: https://github.com/6tail/lunar-javascript (1.7.7의 LunarUtil.ZHI_HIDE_GAN, SHI_SHEN 및 EightChar)
  및 https://6tail.cn/calendar/api.html . 한국 음력 변환과 지역 시각 기준은 위 기존 기준을 유지한다.
- v1/v2 생성기는 별도 파일로 보존하고 기존 암호화 보고서는 업데이트하지 않는다.
  기본 설정은 마이그레이션 이력으로 1회만 v3로 전환하며 이후 관리자 선택은 재시작해도 보존한다.
