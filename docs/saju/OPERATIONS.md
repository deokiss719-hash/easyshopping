# 사주 서비스 운영·출시 안내

## 경로와 상품

- 고객: `/saju`, 자료·정책: `/saju/method`, 복구: `/saju/recover`
- 관리자: 기존 관리자 로그인 후 `/saju/admin` (기존 메뉴에 추가)
- 상품 한 가지: 나의 사주 기본 보고서. 기본 부가세 포함 4,900원. 기존 6,900원 기본 설정만 첫 적용 때 4,900원으로 변경하며, 운영자가 이미 바꾼 가격은 유지합니다.
- 관리자에서 가격(100~1,000,000원), 무료 공개 3/4개 문단, 검증된 보고서 버전, 판매 허용을 설정합니다. 이미 만들어진 주문의 금액은 바뀌지 않습니다.
- 현재 해석 버전 `ko-evidence-1`, 계산 버전 `kr-standard-midnight-1`, 세운 2026~2030 고정. 새 해석 버전은 회귀 검증 후 코드 레지스트리에 추가합니다. 기존 구매 보고서는 재생성하지 않습니다.

## 환경변수 (값은 채팅·Git에 저장하지 않기)

| 이름 | 설정 |
|---|---|
| `SAJU_DATA_KEY` | 독립 난수 32바이트 이상. 출생/보고서 AES-GCM 암호화. 자동 생성해 Render 환경변수에 보관. 변경/분실하면 기존 데이터 복호화 불가. 안전한 운영 비밀 저장소로 백업 필요 |
| `SAJU_PUBLIC_ORIGIN` | `https://easyshoopping.com` |
| `SAJU_PAYMENT_MODE` | `demo`(모의), `test`(PG 테스트), `live`(실과금) |
| `SAJU_TOSS_CLIENT_KEY` | API 개별 연동 클라이언트 키 `test_ck_…` 또는 `live_ck_…` |
| `SAJU_TOSS_SECRET_KEY` | 위 키와 같은 상점/환경 시크릿 `test_sk_…` 또는 `live_sk_…` |
| `SAJU_SELLER_NAME` | 실제 판매자 상호 |
| `SAJU_SELLER_REPRESENTATIVE` | 실제 대표자 |
| `SAJU_SELLER_REGISTRATION` | 사업자등록번호 |
| `SAJU_SELLER_COMMERCE` | 통신판매업 신고번호 또는 실제 면제 근거 |
| `SAJU_SELLER_ADDRESS` | 실제 영업소 주소 |
| `SAJU_SELLER_CONTACT` | 소비자 문의 연락처·이메일 등 |

사주 화면에는 고객 전화번호 입력이 없습니다. 판매자 연락처 고지는 고객 개인정보 수집과 다릅니다.

모든 판매자 항목과 `live` 키가 준비되고 관리자 판매 허용이 켜져야 실결제가 가능합니다. 테스트 키를 라이브처럼 표시하거나 모의 승인을 실제 결제로 기록하지 않습니다. PG 계약은 운영자가 토스페이먼츠에서 디지털 사주 보고서 업종/환불 정책을 사실대로 제출해 심사를 완료해야 합니다.

## 마지막으로 운영자가 준비할 항목

1. 토스페이먼츠 계정·전자결제 계약/심사(사이트와 디지털 콘텐츠 상품). API 개별 연동의 본인 상점 테스트/라이브 키 쌍.
2. 위 실제 판매자 고지 정보와 해당 사업자의 통신판매 관련 준비.
3. Render/DB 처리위탁·국외이전 해당 사항 및 백업 보존기간 확인을 사업자 개인정보처리방침에 반영. 앱은 출생 데이터를 광고/분석/외부 AI로 보내지 않음.
4. 본인 상점 카드 인증을 포함한 PG 테스트 승인/취소 한 번. 운영 카드·인증 앱 입력은 자동화가 대신하지 않음.

시크릿 키는 대화에 붙여넣지 않고 Render 환경변수의 비밀값으로 입력합니다. 저장소에 키 파일/값을 커밋하지 않습니다. 공식 문서 공개 테스트 키는 로컬 검증에만 사용했습니다.

## 결제 상태와 복구

`pending → confirming → paid → refund_requested/refunding → refunded`, 인증 실패/취소는 `failed`.

- 승인 전에 주문 금액·환경 검증. PSP의 주문번호·paymentKey·KRW·금액·잔액·DONE 검증 후만 공개.
- PSP 호출 전에 paymentKey/confirming을 영속화하여 프로세스 중단에도 같은 주문으로 재조회.
- 주문별 고정 Idempotency-Key. 보고서별 유효 주문 하나. DB 행 잠금으로 승인/환불/삭제 경합 제어.
- 승인/취소 응답이 불명확하면 새 주문을 만들지 않고 같은 키로 재확인. 1분 유지보수 주기가 확인 중 주문을 재조회하며 중복 루프 방지.
- 승인 지연 중 보고서 보관 기한이 지났으면 이미 승인된 결제를 자동 환불 대상으로 전환.
- 웹훅 URL: `https://easyshoopping.com/saju/payment-webhook`. `PAYMENT_STATUS_CHANGED`, `CANCEL_STATUS_CHANGED` 등록. 일반 웹훅 본문 자체를 신뢰하지 않고 서버 조회 API로 검증.
- 관리자 상태 확인/전액 환불 버튼. 결제 후 7일 이내 고객 신청은 자동 전액 환불, 그 밖의 신청은 관리자 확인. 3영업일 환급 등 법정 기한을 지킵니다.
- 일부 취소/가상계좌/월 구독은 v1 지원하지 않으므로 PG 관리자에서 임의 부분 취소 대신 이 서비스의 전액 환불을 사용합니다.

## 개인정보·복구 정책

무료 7일, 구매 1년. 1분 주기로 만료 payload 삭제. 유료 금융기록은 5년, 테스트 주문 30일. 불만/분쟁 상담 기록 3년 및 광고 변경 이력 6개월은 운영 채널에서도 별도 준수합니다.

조회 URL은 256비트 난수를 fragment에 넣어 서버 URL 로그에 전달하지 않습니다. 링크 7일/1회, 열람 세션 1시간. 최초 생성 권한도 서버에서 1시간으로 제한. 복구 코드는 원문을 DB에 저장하지 않으며 1회만 화면에 발급합니다. 링크/코드를 함께 로컬 텍스트로 저장할 수 있습니다. 복구하면 이전 열람 세션과 최초 생성 권한을 무효화합니다.

링크/코드 모두 분실하면 자동 본인 확인이 불가능합니다. 주문번호로 환불 문의는 가능하지만 이름/생일만으로 보고서를 재발급하지 않습니다. 기한 경과·삭제 요청 후 데이터 복구도 안 됩니다. 삭제와 환불은 별개입니다.

기록에는 생일·시각·원국·이름을 출력하지 않습니다. 무료 페이지에 기존 Meta 픽셀을 삽입하지 않으며 일반 트래픽 로거보다 먼저 라우팅합니다. 접근 제한은 IP를 키 기반 해시로 바꿔 저장, 최대 1시간 만료. 공개 지표는 날짜/단계/환경/횟수만 보관합니다.

## 검증 및 한계

- `node --test test/saju-*.test.js`: 실제 PostgreSQL WASM(PGlite)에 스키마/트랜잭션 테스트. 운영 DB를 테스트 데이터로 변경하지 않음.
- 한국 음력 공개 변환 사례/윤달, KASI 입춘 시각, 경칩 월주 전환, 자정 vs23시, 1960년 한국 UTC+08:30, 1988년 DST 미존재/중복, 시간 미상/범위, 같은 순간의 지역 비교.
- 금액 변조/외부 승인값 불일치/네트워크 불확실/중복 승인/중복 환불/재조회, 권한 없는 보고서 접근, 링크 단일 사용/복구/만료/삭제/암호화, 관리자 인증/CSRF, 가격 변경 후 구매 보고서 불변.
- 실제 모바일 390×844, 320×740에서 입력·무료·모의 승인·8개 전체 섹션·링크 복구·코드 복구를 확인. 가로 넘침 없음.
- 공식 토스 테스트 키로 카드 결제창 진입·카드사 인증창까지 확인. 카드 앱 본인 인증이 필요하여 실제 PG 승인/취소의 전체 실증은 아직 완료되지 않음. 모의 승인·환불과 PSP 응답 주입 테스트는 실제 PG 거래 성공을 의미하지 않습니다.
- 제3자 달력 구현과 표준시 관례의 한계가 있습니다. 모든 역사적 날짜를 천문연구원 자료와 대조한 것이 아닙니다. 진태양시·용신·왕쇠 정밀 판단·성별 기반 단일 대운은 제공하지 않습니다. 2분 절기 경계와 미확정 기둥을 안내합니다.
